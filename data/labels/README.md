# Людська розмітка (ground truth)

Тут лежить **єдина в проєкті розмітка, зроблена людиною**. Це не звіт і не
результат прогону — це дані. Тому каталог відстежується git, на відміну від
`reports/`, який у `.gitignore`.

## `verdicts_20260820_153940.jsonl`

35 рядків (по одному на повідомлення з `data/test_messages.json`), зібрані через
HTML-звіт `scripts/check_prompt.py` → кнопки в браузері → вивантаження.

Що всередині кожного рядка:

| ключ | зміст |
|---|---|
| `message_id` | id повідомлення в `data/test_messages.json` |
| `field_marks` | оцінка КОЖНОГО поля: `correct` / `invented_ok` / `invented_bad` / `missed` |
| `field_counts` | ті самі оцінки числами |
| `events[].send` | рішення людини: `yes` / `no` — чи годиться подія йти в БД і на модерацію |
| `comment` | вільний коментар рецензента (заповнено в 32 з 35) |
| `in_db`, `auto_worst`, `bad_fields` | похідні, лишені заради сумісності зі старими файлами |

Зведення по всьому файлу: **376 польових суджень** — 312 `correct`,
40 `invented_bad`, 17 `missed`, 7 `invented_ok`; **34 рішення `send`** —
16 `yes`, 18 `no`.

## Як цим користуватися для навчання

- `events[].send` — готові мітки для бінарного класифікатора «чи це анонс
  майбутньої масової події».
- `field_marks` — вказує, які саме поля модель вигадала (`invented_bad`) або
  пропустила (`missed`). Саме звідси будуються ВИПРАВЛЕНІ цільові JSON для
  SFT-датасету: брати сирий вихід моделі як ціль не можна, у ньому 40 вигаданих
  полів.
- Де `_expect` із `data/test_messages.json` розходиться з людським вердиктом —
  **виграє людина**, а розбіжність варто занотувати окремо.

**Це маленька вибірка (n=35).** Вона годиться як ТЕСТОВА, але не як навчальна.
Див. `docs/training-brief.md`, розділ 2.
